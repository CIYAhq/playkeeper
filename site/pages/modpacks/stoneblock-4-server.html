FTB releases a new version every week or two: 1.20.1 on 1 Sep, 1.21.0 on 9 Sep and 1.22.0 on 22 Sep. Your server and your friends' games must run the same one.

On 28 Sep, a server created from its template on the published {{$m.Release}} was online 1 minute 44 seconds after Create, downloads included. Its log said Done (1.357s)!, a timer that leaves out loading the mods.

{{template "h2n" (dict "ID" "memory" "N" 2 "Text" "How much memory StoneBlock 4 needs" "Toc" "How much memory")}}

FTB's listing recommends {{$m.HeapGB}}, with 6 GB as the least, and the pack's CurseForge file asks Java for {{$m.HeapGB}}. That's the heap alone. NeoForge and {{$m.Mods}} mods take memory outside it, so Playkeeper suggests {{$m.Memory}}, of which Java gets {{$m.JavaHeap}}.

On Playkeeper 0.4.3 or older, the first start stops with invalid dist DEDICATED_SERVER. Status Effect Bars, a mod for players' screens that CurseForge doesn't mark as one, goes on the server, and the pack's default-server.properties switches off Playkeeper's console and allowlist. Update Playkeeper: {{$m.Release}} leaves the mod off and keeps its own settings.

{{template "h2n" (dict "ID" "four-files" "N" 4 "Text" "The four files you add by hand" "Toc" "Files to add")}}

StoneBlock 4 has no server files on CurseForge to take these from, so Playkeeper lists a step for each, with its page:

  • BetterBlockZ, ServerCore and Create: Shimmer. Their authors allow downloads only through the CurseForge app. Download each jar from its page and upload it to mods on the Files tab.
  • Hostile Neural Networks: Extra Data Models, ExtraDataModels-1.21-4.4.2.zip, is a data pack, not a mod. Upload it to datapacks, the folder beside mods that holds the pack's other data packs. FTB's own installer puts it there.

The server starts without them, as the 28 Sep one did. Add them before friends join, then restart it.

{{template "h2n" (dict "ID" "manual" "N" 5 "Text" "By hand, with FTB's installer" "Toc" "By hand")}}

FTB publishes StoneBlock 4's server on its own site rather than CurseForge, as an installer. It downloads the pack from FTB's list, which has the three mods and the data pack, and leaves Status Effect Bars off. The itzg Docker image, which Playkeeper runs servers in too, runs that installer for you:

# {{$m.Label}} {{$m.Version}} on Java {{$m.Java}}: {{$m.Memory}} in all, {{$m.JavaHeap}} of it Java's heap
docker run -d --name stoneblock-4 -p 25565:25565 \
  --memory {{gbFlag $m.MemoryMB}} --memory-swap {{gbFlag $m.MemoryMB}} \
  -e EULA=TRUE -e MEMORY={{gbFlag $m.JavaHeapMB}} -e USE_AIKAR_FLAGS=TRUE \
  -e TYPE=FTBA -e FTB_MODPACK_ID=130 -e FTB_MODPACK_VERSION_ID=100515 \
  -v stoneblock-4-data:/data itzg/minecraft-server:java{{$m.Java}}
  • 130 is the pack in FTB's list, and 100515 its version {{$m.Version}}. Without FTB_MODPACK_VERSION_ID the image takes FTB's newest version, and a new number installs that version over the old one.
  • It ran on 28 Sep: FTB's installer put {{$m.TypeName}} {{$m.Loader}} and the pack in place, restricted mods included, and the server said Done about 75 seconds after its container started.
  • Open TCP 25565 in your provider's firewall.
{{template "h2n" (dict "ID" "settings" "N" 6 "Text" "The settings StoneBlock 4 brings" "Toc" "Settings")}}

The pack's default-server.properties sets these on a new server, and Playkeeper {{$m.Release}} keeps them:

SettingValueWhat it means
allow-flighttrueFlying with mod items doesn't get players kicked.
allow-netherfalseNobody can travel to the Nether.
enable-command-blocktrueCommand blocks run.
spawn-protection512Only operators can change blocks within 512 blocks of the world's spawn.

It also sets bug-report-link, which Playkeeper doesn't take from packs. New server says so before you create the server.
