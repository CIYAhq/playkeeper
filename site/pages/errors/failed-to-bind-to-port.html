Minecraft 1.21.1's log, on Linux

Starting Minecraft server on *:25577 **** FAILED TO BIND TO PORT! The exception was: io.netty.channel.unix.Errors$NativeIoException: bind(..) failed: Address already in use Perhaps a server is already running on that port?

The server tried to take its port, couldn't, and stopped. Read the line that starts with "The exception was": it names the reason. The last line is printed whatever the reason, so it can be wrong.

{{template "h2n" (dict "ID" "reasons" "N" 2 "Text" "Three reasons, from our tests" "Toc" "The reasons")}}

On 29 Sep we started Minecraft 1.21.1's own server jar on Linux, as a normal user, three ways:

What was wrongThe exception, on LinuxOn Windows, Java 21
Another program already listened on the portbind(..) failed: Address already in usejava.net.BindException: Address already in use: bind
server-ip=203.0.113.10, an address the machine doesn't havebind(..) failed: Cannot assign requested addressjava.net.BindException: Cannot assign requested address: bind
server-port=80, as a user that isn't rootbind(..) failed: Permission deniedDoesn't apply

Linux servers use Netty's own network code, hence NativeIoException. With use-native-transport=false, Java's standard networking, which Windows and macOS always use, the first case read java.net.BindException: Address already in use, and Windows adds : bind.

{{template "h2n" (dict "ID" "fixes" "N" 3 "Text" "The fix for each" "Toc" "Fixes")}}
  • Address already in use: find what has the port. Often it's the same server started twice, an old copy still running in another window or session. On Linux, sudo ss -ltnp 'sport = :25565' names the program; on Windows, netstat -ano | findstr :25565 gives its process ID. Stop it, or give your server another port with server-port, like 25566.
  • Cannot assign requested address: empty server-ip. With it empty the server listens on every address the machine has, which is what you want almost always.
  • Permission denied: use a port from 1024 up. Linux keeps the ports below 1024 for root. Use 25565 and put a DNS SRV record in front, if you want an address without a port.
  • Inside one server, two things on one port: an RCON port or a plugin's own port set to the game's port clashes with it. Query can share it: ours ran with query.port on the game's port, since query uses UDP and the game TCP.

  • Each server gets its own port, 25565 for the first and one more from 25566 for each further server, so two of yours never ask for the same one.
  • When another program has a server's port, the Overview says Port 25565 is already in use, with a button to give the server a different port.
  • When it happens inside the server, it explains the cause: a plugin, a mod or RCON set to the game's port, or a server-ip the machine doesn't have.
