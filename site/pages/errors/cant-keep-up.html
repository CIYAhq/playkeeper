From our test server's log

[13:07:46 WARN]: Can't keep up! Is the server overloaded? Running 2505ms or 50 ticks behind

Every tick, the server moves mobs, grows crops, runs redstone and answers players, and it has 50 ms for each tick to keep 20 a second. The warning is the server noticing it's behind its schedule: 2505 ms is 50 ticks of 50 ms. It's a warning, not a crash, but players feel the lost ticks as lag.

{{template "h2n" (dict "ID" "tests" "N" 2 "Text" "What made ours fall behind" "Toc" "Our tests")}}

On 29 Sep we ran a Paper 1.21.1 server with nobody on, and pushed it three ways:

What we didWhat it loggedTPS over the last minute
Allowed it one CPU core, and loaded 256 chunks nobody had visitedRunning 32910ms or 658 ticks behind12.92
Cut its CPU to a twentieth of a coreRunning 2505ms or 50 ticks behind, once19.2, with one tick taking 700 ms
Put 333 villagers in one chunk, on one coreNothing20, with ticks of 6.6 ms

Generating land was the worst by far: making new chunks is heavy work, and the server waits for the ones it has to load. An empty server needs little CPU, so even a twentieth of a core fell behind only once, and a few hundred villagers were well within one core.

{{template "h2n" (dict "ID" "fixes" "N" 3 "Text" "The fixes, most useful first" "Toc" "Fixes")}}
  • Pre-generate the map around spawn before friends explore, with the Chunky plugin or mod. The server then loads land from disk instead of making it while players wait.
  • Give it a faster core. Minecraft runs each world's ticks on one thread, so one fast core beats many slow ones. On a VPS, a plan with dedicated cores stops neighbours taking your CPU time.
  • Give it enough memory. A heap that's nearly full makes Java stop to clean up more often, and each stop is time the ticks don't get. The sizing guide gives a size for what you run.
  • Keep less of the world running. Lower simulation-distance in server.properties, the chunks around each player where mobs and crops move.
  • A single warning at start-up or after a burst of work, with the TPS back at 20, needs nothing.

> tps
TPS from last 1m, 5m, 15m: 12.92, 18.02, 19.24
> mspt

0.2/0.1/1.2, 0.1/0.1/1.2, 4.6/0.1/605.2

20 TPS is on time. Tick times under 50 ms leave room; the maximum shows the stalls.
